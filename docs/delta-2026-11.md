# Delta note: July 2026 field lab → Supermemory as of Nov 2026

**Date:** 2026-11-05 · **Scope:** public docs, changelogs, and OpenAPI only · **Live re-verification:** blocked (see below)

The July 2026 field lab (evidence passes dated 2026-07-16/17) tested the **v3/v4 API**. On
**2026-10-07 Supermemory shipped API v5**, a breaking, namespace-scoped redesign. Most of the
lab's v3/v4 observations still describe the legacy surface, which is still served. However,
several **patterns the lab recommended rely on legacy-only operations that have no v5
replacement**. That is the headline for anyone reading the July verdict today.

Labels follow the repo convention: **Documented** (official docs/changelog/OpenAPI as fetched
2026-11-05), **Inferred** (our reading), **Unverified** (not re-run live in Nov 2026).

## 1. The big change: API v5 (2026-10-07)

**Documented.**

- **Namespaces replace container tags.** Scope moves into the URL: `/ns/{namespace}/...`.
  A v5 document lives in exactly one namespace, so multi-tag writes do not exist in v5.
  The namespace pattern is unchanged: `^[a-zA-Z0-9_:-]+$`, ≤100 chars.
- **Renames:** `containerTag`→path, `customId`→`id`, `entityContext`→`supportingContext`,
  `filterByMetadata`→`group`, `documentDate`→`date`, `q`→`query`, `filters`→typed `filter`,
  search mode `documents`→`chunks`.
- **Changed search defaults in v5:** `searchMode` defaults to `hybrid` (v4: `memories`),
  `threshold` to `0.3` (v4: `0.6`), `rerank` to `"none"`, and `rewriteQuery` to `false`.
- **Explicit write semantics:** `POST /ns/{ns}/document` with an existing `id`
  appends/diffs. `PATCH /ns/{ns}/document/{id}` replaces and reprocesses. File replace and
  partial update have their own routes.
- **Unified listing:** `POST /ns/{ns}/list/{documents|chunks|memories}` with cursor pagination
  (2026-11-02). Processing state is now `system.status` / `system.dreamingStatus` on each item,
  and there is no separate processing endpoint.
- **Forgetting:** exact `DELETE /ns/{ns}/memories` (1–500 IDs, per-ID `matches`/`errors`),
  semantic `DELETE /ns/{ns}/memories/semantic` (`dryRun` required, ≤100 selected per request).
- **Namespace lifecycle:** `DELETE /ns/{ns}` deletes the namespace permanently.
  `DELETE /ns/{ns}?moveTo=target` replaces container merge. Footgun: `moveTo` sent in the
  JSON body is ignored, and the namespace is **permanently deleted**.
- **Organization:** `/organization` replaces `/v3/settings` and is reduced to shared context
  plus namespace count.
- **SDKs:** TS and Python `supermemory` ≥5.0.0 speak v5 only; older versions speak v3/v4.
  `@supermemory/tools` 3.0 uses v5 names, and `@supermemory/ai-sdk` is retired.
  The CLI renamed `--tag`→`--namespace` and dropped `remember`, `update`, and `tags merge`.
  `npx supermemory migrate` drives a coding agent through the migration.
- **No sunset date** for v3/v4 was found in the docs or changelog. Legacy `/v3/openapi` and
  `/v4/openapi` are still served, while the root `/openapi.json` now serves v5.

### Operations the lab relied on that have **no v5 replacement**

**Documented** in the migration guide's "Operations without a direct replacement" section and
the SDK table:

| Legacy operation (July lab usage) | v5 status |
|---|---|
| Direct memory creation `POST /v4/memories` (exact confirmed facts, profile-visible ≈1 s) | **Removed.** Ingest a document with `dreaming: "instant"` instead. |
| Versioned memory update `PATCH /v4/memories` (parent/root lineage, version 2/3 chains) | **Removed.** Update the source document instead. |
| Conversation upsert `POST /v4/conversations` | **Removed.** Use `add` with a stable `id` per conversation. |
| `documents.fileUrl` (temporary signed source URL) | **Removed**, no replacement |
| `settings.suggestBuckets` and `settings.reset` | **Removed**, no replacement |
| Container merge plus merge status | Replaced by `DELETE /ns/{src}?moveTo=dst` (one source per call, `operationId`) |
| `reason` field on forget | **Removed** |
| Connector resource listing (`/v3/connections/{id}/resources`) | Use `connectors.get` with `include: ["syncs","picker"]` |

**Inferred impact on July recommendations.** The "write confirmed decisions directly"
pattern, the versioned decision journal, the preference agent's versioned replacement, the
curator's parent/root lineage, and the Project Memory OS version chain were all built on
direct v4 memory writes and versioned updates. They keep working on the legacy surface today.
On v5 they must be rebuilt on documents: stable document `id` plus `PATCH`-replace, with
lineage held in the application ledger. Whether v5 `dreaming: "instant"` matches the July
direct-write readiness (≈1 s profile visibility) is **unverified**, and it should be the first
thing re-measured. The docs themselves warn that under `dynamic`, a fresh namespace can show
zero memories for **several minutes**.
